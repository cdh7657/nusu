# 관리앱(주택관리) ↔ 누수알림기 연동 사양

관리앱 소스는 비공개 저장소에 있어서 이번에는 고치지 않았습니다. **관리앱을 고치지 않아도 연동은 이미 됩니다.**
고객이 알림 화면에서 출동 접수를 누르면 기존 `/requests`로 들어가기 때문입니다.
아래 내용은 관리앱에 누수 화면을 더 붙이고 싶을 때 쓰는 기준입니다.

## 1. 지금 바로 되는 것 (변경 없음)

- 접수: 기존 `/requests/{접수번호}`에 들어옵니다.
  - `work: "누수"`
  - `note`의 첫 줄: `[누수알림기 ABCDE-FGHJK] 알림: … / 잠금 테스트: 10분 2.95→2.50 bar`
- 일정·출발·완료 보고서: 관리앱이 지금처럼 `/reqstatus/{접수번호}`에 쓰면, 고객앱 홈에 그대로 뜹니다.

## 2. 관리앱에 붙일 수 있는 것

| 하고 싶은 것 | 방법 |
|---|---|
| 누수알림기 목록·상태 | `GET https://asia-southeast1-daewon-booking.cloudfunctions.net/leakAdmin?k=관리키&op=list` |
| 장치 상세(압력·48시간 기록·알림) | `…/leakAdmin?k=관리키&op=dev&dev=코드10자` |
| 기준값 조정 | `POST …/leakAdmin?k=관리키&op=cfg&dev=코드` 본문 `{"riseBar":0.06,"flowBar":0.08,"flowMin":60,"mode":"prv","learnUntil":epoch초}` |
| 관리앱으로 푸시 받기 | 관리앱 WebView에서는 웹 푸시가 안 됩니다. 관리 화면(leak-admin.html)을 홈 화면에 추가해서 쓰거나, 관리앱에 FCM(안드로이드)을 넣고 토큰을 `op=token`으로 등록합니다 |
| 접수 메모에서 장치 찾기 | 정규식 `\[누수알림기 ([A-Z0-9]{5})-([A-Z0-9]{5})\]` → 코드 = 두 묶음을 붙인 것 |

## 3. 데이터 구조

```
/leak/{코드}/st        {t, p, base, rssi, fw, mode}                장치가 10분마다
/leak/{코드}/hist/{YYYYMMDDHH} {mn, mx, av, rf(톱니 수), us(사용 수)}   장치가 1시간마다
/leak/{코드}/alerts/{id} {type: drip|decay|flow|offline, t, p, base, period, learning,
                        ack: use|test|book, test:{res,p0,p1}, sent:{cust,adm}}
/leak/{코드}/live      {t, p}                                       잠금 테스트 중 2초마다
/leak/{코드}/cmd       {testUntil, ack}                             고객앱 → 장치
/leak/{코드}/cfg       {mode, learnUntil, base, riseBar, flowBar, flowMin, pmax, zeroV}
/leak/{코드}/owner     {name, phone, house, addr, addr2, at}
/leak/{코드}/tokens/{해시} "FCM토큰"
/leakIndex/{코드}      {name, phone, house, addr, mode, at, seen, last, offAt}   (밖에서 읽기 금지)
/leakAdmin/key, /leakAdmin/tokens                                   (밖에서 읽기·쓰기 금지)
/config/push           {vapid}
```
